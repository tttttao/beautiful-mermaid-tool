## 2024-05-30 - Accessible Visual Feedback on Buttons
**Learning:** When adding temporary visual feedback states to buttons (e.g., swapping an icon on click to indicate success), screen readers can double-announce or incorrectly interpret dynamic changes to the primary `aria-label` or `title`. Also, unmanaged timeouts for temporary UI states can cause memory leaks or overlapping state resets if the user clicks rapidly or unmounts the component.
**Action:** Use a separate visually hidden `aria-live="polite"` element for accessible status announcements. Keep the main button's `aria-label` constant. Always clear existing timeouts before starting a new one and clear them in the `onBeforeUnmount` lifecycle hook. Apply visual state colors directly to the icon rather than conditionally manipulating parent classes to avoid Tailwind specificity issues.
